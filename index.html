P/01个人项目

SQL 数据分析 Agent 后训练

给 Qwen3-4B 做多轮 SQL 分析 Agent 的后训练，在 BIRD 上依次比较拒绝采样微调、偏好优化、大模型蒸馏和在线强化学习，每轮先写预注册再上 H20 跑，4B 的官方执行准确率从 49.5% 提到 57.9%。

  • Agent 与评测模型在只读 SQLite 沙箱里先查表、试跑 SQL、看到结果再提交，评测按数据库隔离、全程看不到金标；判分比官方 EX 更严，主比较用按数据库聚类的 bootstrap 区间判定，结论不成立也照实记录。
  • 离线训练发现只监督最终答案会把“先查再交”的习惯训没，改为对执行验证过的整条多轮轨迹做拒绝采样微调，再接 DPO；235B 老师先在开发集上证明比学生强 5 个点以上，才用来蒸馏、补到学生做不对的题上。
  • 在线强化学习以执行结果为奖励做 RLOO，LoRA 每步热更新到 vLLM 采样端；对照里 FSDP2 全参数分布式版本反而比 LoRA 低 4.2 个点，在线蒸馏也没超过离线蒸馏；最终只在起点时对时错的边界题上训练，按更严的项目判分比起点再高 2.6 个点、过了预注册检验。

P/02个人项目

Mini 秒杀高并发下单系统

聚焦秒杀下单主链路，解决库存不超卖、用户不重复下单、瞬时流量不打穿数据库。

  • 下单链路Redis Lua 原子预扣库存，MySQL 唯一索引兜底，订单经本地消息表和 RabbitMQ 异步落库，Redis 宕机时宁可拒单也不超卖。各轮压测零超卖、零重复下单，售罄尾部 p99 由 98 ms 降到 12 ms。
  • 多实例库存协调进程在预扣和落库之间被暂停或强杀时，库存不丢也不多退，醒来的旧节点过不了租约和版本号校验。同机三个 JVM 注入 9 个故障与负载场景，全部通过，协议多出的 Redis 往返也已压回改造前水平。
  • 性能瓶颈入口线程大多卡在等数据库连接，我没有扩连接池，而是削减入口的同步 SQL，单实例入口稳定档由 3000/s 提到 4000/s。换到独占云服务器后又定位到 RabbitMQ 发布端 channel 缓存不足，调整后由 3500/s 提到 4000/s。

P/03课题组研究项目

成本约束下的机器学习选股与滚动验证

研究机器学习选股扣除交易成本后还剩多少超额。在沪深全 A 上做 2020–2024 年滚动样本外回测，冻结的方案现在每天收盘后跑模拟盘。

  • 数据与回测样本保留 245 只区间内退市股，只用当时可见的数据；账本按 T+1、涨跌停、停牌和整手逐笔成交。市盈率、市净率数据抽查发现可能含未来信息，按事先定的规则，183 个因子里的估值因子整组弃用。
  • 检验与结论10 个量价特征加成本约束的简单方案，样本外日秩 IC 0.086，扣除成本后年化信息比率只有 0.41。因子库加均值方差组合的复杂方案在块 bootstrap 检验下没有显著跑赢它（p = 0.84），按看结果前写定的规则冻结简单方案，2025 年保留期只开一次。
  • 归因与模拟盘自建风险模型归因显示，开发期超额主要来自低特质波动、低流动性两个风格，分数剔除行业和风格后 IC 只剩约四分之一。模拟盘每天收盘后由云端定时任务运行，交易代码用哈希锁定，记录只追加，日报逐日拆解风格贡献。
